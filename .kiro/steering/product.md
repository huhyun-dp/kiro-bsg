# Product Overview

## 프로젝트 개요

**BSG Partners** - 세션 기반 인증 시스템 데모 애플리케이션입니다.
Spring Boot + MyBatis + MySQL 조합으로 구현된 회원 인증/관리 웹 서비스입니다.

## 핵심 기능

### 인증 (Authentication)
- **회원가입**: 이름, 이메일, 휴대폰 번호, 비밀번호를 입력받아 회원 등록
- **로그인**: 이메일/비밀번호로 인증 후 세션 발급
- **로그아웃**: 세션 무효화 및 로그인 페이지 리다이렉트

### 회원 관리 (ADMIN 전용)
- **접근 권한**: 회원 관리 화면(`/members`)과 회원 목록 API(`/api/members`)는 `ADMIN` 에게만 허용한다. `OPERATOR`/`VIEWER` 는 메뉴가 보이지 않고, 직접 접근 시 화면은 HTTP 403, API 는 HTTP 403 JSON 을 받는다.
- **회원 목록 조회**: 등록된 전체 회원 목록을 TOAST UI Grid로 표시
- **회원 검색**: 이름, 이메일, 휴대폰 번호 키워드 검색
- **개인정보 보호**: 휴대폰 번호 마스킹 처리 (예: `010-****-5678`)

### 권한 관리 (Access Management, ADMIN 전용)
- **메뉴 구조**: 로그인 후 좌측 사이드바는 `회원 관리`, `문의 요청`, `권한 관리` 로 구성한다. `회원 관리`(`/members`)와 `권한 관리`(`/admin/access`)는 `ADMIN` 에게만 노출하고, `문의 요청`(`/inquiries`)은 모든 로그인 회원에게 노출한다.
- **역할**: `ADMIN` / `OPERATOR` / `VIEWER` (신규 가입 기본값 `VIEWER`)
- **계정 상태**: `ACTIVE` / `SUSPENDED` (신규 가입 기본값 `ACTIVE`)
- **목록**: 이름·이메일·휴대폰 검색, 역할/상태 필터, 서버 사이드 페이지네이션, 전체 건수 표시
- **변경**: 회원 한 명의 역할/상태를 변경 사유와 함께 변경, 저장 전 확인 UI, 낙관적 잠금(version) 충돌 시 재조회 안내
- **감사 로그**: 모든 역할/상태 변경을 변경과 동일 트랜잭션으로 기록하고 최신순 페이지네이션으로 조회

## 주요 사용자 흐름

1. 미인증 사용자가 `/` 접근 → `/login` 자동 리다이렉트
2. 로그인 성공 → `/inquiries` (문의 요청 목록)로 이동
3. `ADMIN` 이 `회원 관리` 메뉴 → `/members` 진입 → AJAX로 `/api/members` 호출 → TOAST UI Grid 렌더링
4. 인증 없이 `/members` 또는 `/api/**` 접근 → 각각 로그인 리다이렉트 / HTTP 401 응답
5. `OPERATOR`/`VIEWER` 가 `/members` 또는 `/api/members` 직접 호출 → 각각 HTTP 403 / HTTP 403 JSON
6. `ADMIN` 이 `권한 관리` 메뉴 → `/admin/access` 진입 → AJAX로 `/api/admin/members` 호출 → 목록 렌더링, 회원 선택 후 역할/상태 변경 및 감사 로그 조회
7. 비관리자가 `/admin/access` 직접 호출 → HTTP 403, 미인증 사용자는 로그인 화면으로 이동

## 비즈니스 규칙

- 이메일은 대소문자 구분 없이 유일해야 함 (저장 시 소문자로 정규화)
- 휴대폰 번호는 한국 이동통신 번호 형식만 허용 (`010XXXXXXXX`, 숫자 11자리)
- 비밀번호는 영문+숫자 조합 8~64자 필수
- 회원 가입 시 이용약관 동의 필수

### 권한 관리 규칙
- 신규 가입자는 기본적으로 `VIEWER`, `ACTIVE` 상태
- `ADMIN` 만 역할/상태를 변경할 수 있고, `OPERATOR`/`VIEWER` 는 권한 관리 메뉴·API 사용 불가
- `SUSPENDED` 회원은 로그인 불가, 로그인 이후 정지된 회원의 기존 세션도 다음 요청에서 차단하고 세션 무효화
- 현재 로그인한 관리자는 자기 자신의 역할을 낮추거나 계정을 정지할 수 없음
- 시스템에는 활성 상태의 `ADMIN` 이 최소 1명 이상 남아 있어야 함
- 동시 수정은 `version`(낙관적 잠금)으로 감지하여 충돌 시 HTTP 409 반환
- 모든 규칙은 클라이언트가 아닌 서버에서 다시 검증하며, 초기 관리자는 `BOOTSTRAP_ADMIN_EMAIL` 로 지정

## 보안 원칙

- Spring Security를 사용하지 않고 커스텀 보안 레이어로 구현
- 존재하지 않는 계정 로그인 시에도 BCrypt 비교를 수행해 타이밍 공격 방어
- 세션 고정 공격(Session Fixation) 방어: 로그인 성공 시 `changeSessionId()` 호출
- 커스텀 CSRF 토큰 필터로 CSRF 공격 방어 (timing-safe 비교)
- 에러 응답에 스택 트레이스/상세 메시지 미노출

## 서비스 도메인

- `lx_auth` 데이터베이스 사용
- 세션 쿠키명: `BSG_SESSION`
- 세션 유효 시간: 30분


### 문의 요청(Inquiry)
- 로그인 회원은 문의 목록·상세·첨부 다운로드를 이용할 수 있으며, 작성자 본인만 `GET /inquiries/{id}/edit` 및 multipart `POST /inquiries/{id}/edit`로 제목·내용을 편집할 수 있다.
- 문의 상세 조회 시 작성자 본인이 자신의 문의를 열람하면 조회수가 증가하지 않는다(셀프 카운트 방지). 작성자가 아닌 회원이 조회하면 조회수가 1 증가한다.
- 편집은 기존 첨부를 기본 보존하고 `deleteAttachmentIds`로 선택한 파일만 개별 삭제하며 새 파일을 추가할 수 있다.
- 최종 첨부는 최대 5개·20 MiB이고, 새 파일 하나는 최대 10 MiB다. PDF/PNG/JPEG만 확장자·선언 MIME·서명을 모두 확인해 허용한다.
- 편집 상태 변경은 CSRF 보호를 받고, 비작성자는 파일 또는 문의를 변경할 수 없다.

> 문의 편집의 테스트/빌드 검증은 이 문서 갱신 시 수행하지 않았다. 9.7.8과 9.7.9는 사용자 요청으로 건너뛴 상태다.
