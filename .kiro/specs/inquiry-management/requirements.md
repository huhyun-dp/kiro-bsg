# Requirements Document

## Introduction

이 문서는 **BSG Partners** 회원관리 웹 애플리케이션에 추가된 **문의 요청(Inquiry)** 기능의 구현 기준 요구사항을 정리한 것입니다.

로그인한 회원이 문의를 작성하고, 전체 문의 목록을 페이지 단위로 조회하며, 개별 문의 상세를 열람(조회수 증가)할 수 있습니다. 실제 구현 코드를 직접 확인하여 작성되었습니다.

> **분석 기준:** 현재 구현 코드 직접 확인
> **관련 커밋:** `fix: 문의 스키마를 Liquibase로 통합하고 공통 사이드바 적용`, `docs: README에 문의 요청 기능 및 사용 안내 추가`
> **표기 규칙:**
> - ✅ 확인됨 — 실제 구현 코드에서 직접 확인한 사실
> - 🔶 추정 — 구현을 근거로 판단했으나 담당자 확인 권장
> - ❓ 확인 필요 — 코드만으로는 정확히 알 수 없는 내용

이 기능은 기존 두 스펙([`member-auth-baseline`](../member-auth-baseline/), [`member-access-management`](../member-access-management/))과 독립적인 별도 기능이므로 별도 스펙으로 관리합니다. 좌측 사이드바 최상위 메뉴는 현재 `회원 관리`, `문의 요청`, `권한 관리(ADMIN 전용)`로 구성됩니다.

---

## Glossary

- **문의(Inquiry)**: 로그인한 회원이 작성하는 제목·내용 기반의 게시글
- **작성자(Author)**: 문의를 등록한 회원. 상세 화면에는 작성자 이름이 표시됨
- **조회수(View Count)**: 문의 상세를 열람한 누적 횟수. 생성 시 0에서 시작
- **문의 목록**: 전체 문의를 최신순으로 페이지 단위 표시하는 화면
- **인증된 회원**: 로그인에 성공한 사용자. 문의 기능은 로그인해야 사용 가능

## Requirements

### Requirement 1: 문의 목록 조회

**User Story:** As an 인증된 회원, I want 등록된 문의를 페이지 단위로 조회할 수 있기를, so that 전체 문의 현황을 파악할 수 있다.

#### Acceptance Criteria

1. WHEN 인증된 회원이 `/inquiries`에 접근하면, THE System SHALL 전체 문의 목록을 최신순(작성일시 내림차순, 동일 시각은 ID 내림차순)으로 표시한다. ✅
2. THE System SHALL 목록을 페이지당 10건으로 서버 사이드 페이지네이션한다. ✅
3. THE System SHALL 요청 페이지 번호를 1 이상 전체 페이지 수 이하로 보정(clamp)한다. ✅
4. THE System SHALL 문의가 한 건도 없을 때 전체 페이지 수를 1로 처리한다. ✅
5. THE System SHALL 목록 항목에 문의 ID, 제목, 조회수, 작성일시를 표시하고 전체 건수와 현재/전체 페이지를 제공한다. ✅
6. THE System SHALL 이전/다음 페이지 이동 가능 여부(`hasPrevious`/`hasNext`)를 제공한다. ✅

---

### Requirement 2: 문의 작성

**User Story:** As an 인증된 회원, I want 제목과 내용을 입력해 문의를 등록할 수 있기를, so that 담당자에게 요청을 전달할 수 있다.

#### Acceptance Criteria

1. WHEN 인증된 회원이 `/inquiries/new`에 접근하면, THE System SHALL 문의 작성 폼을 표시한다. ✅
2. THE System SHALL 제목을 필수 입력으로 하고 20자 이하로 제한한다. ✅
3. THE System SHALL 내용을 필수 입력으로 하고 500자 이하로 제한한다. ✅
4. IF 입력값 유효성 검사에 실패하면, THEN THE System SHALL 작성 폼을 유지하고 오류 메시지를 표시한다. ✅
5. WHEN 작성이 성공하면, THE System SHALL 현재 로그인 회원을 작성자로 저장하고 조회수를 0으로 초기화한다. ✅
6. THE System SHALL 작성일시를 한국 표준시(Asia/Seoul) 기준으로 저장한다. ✅
7. WHEN 작성이 성공하면, THE System SHALL 방금 생성된 문의 상세 화면(`/inquiries/{id}`)으로 이동한다. ✅
8. THE System SHALL 문의 등록(POST) 요청에 CSRF 토큰을 적용한다. ✅

---

### Requirement 3: 문의 상세 조회 및 조회수 증가

**User Story:** As an 인증된 회원, I want 개별 문의의 상세 내용을 볼 수 있기를, so that 문의 내용과 작성자를 확인할 수 있다.

#### Acceptance Criteria

1. WHEN 인증된 회원이 `/inquiries/{id}`에 접근하면, THE System SHALL 해당 문의의 제목, 내용, 작성자 이름, 조회수, 작성일시를 표시한다. ✅
2. WHEN 문의 상세를 조회하면, THE System SHALL 해당 문의의 조회수를 1 증가시킨다. ✅
3. THE System SHALL 상세 화면에 표시되는 조회수를 증가 반영된 값으로 표시한다. ✅
4. THE System SHALL 작성자 이름을 회원 테이블과 조인하여 조회한다. ✅
5. IF 존재하지 않는 문의 ID로 접근하면, THEN THE System SHALL HTTP 404를 반환한다. ✅

---

### Requirement 4: 접근 제어 및 메뉴

**User Story:** As a 시스템, I want 로그인한 회원만 문의 기능을 사용하도록 제한할 수 있기를, so that 미인증 접근을 차단한다.

#### Acceptance Criteria

1. WHEN 미인증 사용자가 `/inquiries/**`에 접근하면, THE System SHALL 로그인 화면으로 이동시킨다. ✅
2. THE System SHALL 로그인 후 좌측 사이드바에 `문의 요청` 메뉴를 모든 로그인 회원에게 노출한다. ✅
3. THE System SHALL 문의 화면에서 `문의 요청` 메뉴를 활성 상태로 표시한다. ✅
4. THE System SHALL 공통 헤더/사이드바 fragment(`fragments/layout`)를 재사용한다. ✅

## 업무 규칙 요약

| 번호 | 규칙 | 확인 상태 |
|------|------|-----------|
| IR-01 | 문의는 로그인한 회원만 작성·조회할 수 있다 | ✅ |
| IR-02 | 제목은 필수이며 20자 이하여야 한다 | ✅ |
| IR-03 | 내용은 필수이며 500자 이하여야 한다 | ✅ |
| IR-04 | 신규 문의의 조회수는 0에서 시작한다 | ✅ |
| IR-05 | 문의 상세를 열람할 때마다 조회수가 1 증가한다 | ✅ |
| IR-06 | 목록은 작성일시 내림차순(동일 시각 ID 내림차순), 페이지당 10건이다 | ✅ |
| IR-07 | 작성일시는 한국 표준시(Asia/Seoul) 기준으로 저장한다 | ✅ |
| IR-08 | 작성자는 세션의 현재 로그인 회원으로 설정한다 | ✅ |

## 확인이 필요한 사항

| 번호 | 확인 항목 | 이유 |
|------|-----------|------|
| Q1 | 문의를 작성자 본인만 볼 수 있어야 하는가, 아니면 로그인한 모든 회원이 전체 문의를 조회해도 되는가? | 현재는 로그인한 모든 회원이 전체 목록과 상세를 조회할 수 있다 |
| Q2 | 조회수는 본인 조회도 증가시키는 것이 맞는가(중복 조회 방지 필요 여부)? | 현재는 접근할 때마다 무조건 1 증가한다 |
| Q3 | 문의에 대한 답변(관리자 회신) 기능이 필요한가? | 현재는 작성·조회만 있고 답변/상태 관리가 없다 |
| Q4 | 문의 수정·삭제 기능이 필요한가? | 현재 미구현 |
| Q5 | ADMIN/OPERATOR 등 역할에 따라 문의 접근·관리 권한을 차등할 필요가 있는가? | 현재 역할과 무관하게 로그인 회원 모두 동일하게 접근한다 |

---

## 현재 구현되지 않은 기능 (개선 검토 후보)

- 문의 수정 / 삭제
- 문의 답변(관리자 회신) 및 처리 상태(접수/처리중/완료)
- 작성자 본인 문의만 필터링 조회
- 문의 검색(제목·내용 키워드)
- 첨부파일 업로드
- 조회수 중복 증가 방지(동일 사용자 재조회 시)
