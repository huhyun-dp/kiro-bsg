# Requirements Document

## Introduction

이 문서는 **BSG Partners** 조직 내부에서 사용하는 **회원관리 웹 애플리케이션**의 현재 구현 기준 요구사항을 정리한 것입니다.

내부 PI/PO 업무 인수인계를 목적으로 작성되었으며, 실제 구현 코드를 직접 확인하여 작성되었습니다.

> **분석 기준일:** 2025년 현재 구현 코드 직접 확인  
> **표기 규칙:**
> - ✅ 확인됨 — 실제 구현 코드에서 직접 확인한 사실
> - 🔶 추정 — 구현을 근거로 판단했으나 담당자 확인 권장
> - ❓ 확인 필요 — 코드만으로는 정확히 알 수 없는 내용

사용자는 이메일과 비밀번호로 계정을 만들고 로그인한 뒤, 전체 회원 목록을 조회하거나 이름·이메일·휴대폰 번호로 검색할 수 있다. 외부 일반 이용자에게 공개되는 서비스가 아니라 **내부 운영 담당자**가 사용하는 관리 화면으로 추정된다.

---

## Glossary

- **System**: 본 회원관리 웹 애플리케이션 전체
- **미인증 방문자**: 로그인 전 사용자. 회원가입·로그인 화면에만 접근 가능
- **인증된 회원**: 로그인에 성공한 사용자. 회원 관리 화면 이용 가능
- **세션(Session)**: 로그인 상태를 유지하는 서버 측 인증 수단. 쿠키 방식으로 관리됨
- **CSRF 토큰**: 위조 요청 방지 코드. 상태 변경 요청(POST)에 포함되어 검증됨
- **한국 표준시(KST)**: Asia/Seoul 기준 UTC+9 시간대
- **BCrypt**: 비밀번호를 단방향 해시로 변환하는 암호화 알고리즘 (강도 기본 12)
- **멱등성**: 같은 작업을 반복해도 결과가 동일한 성질
- **마스킹**: 개인정보 보호를 위해 일부 문자를 숨기는 처리 (예: `010-****-5678`)
- **세션 고정(Session Fixation) 공격**: 로그인 전 세션 ID를 로그인 후에도 재사용하도록 유도하는 공격 기법

## Requirements

### Requirement 1: 회원가입

**User Story:** As an 내부 운영 담당자, I want 이메일과 비밀번호로 계정을 신규 등록할 수 있기를, so that 시스템에 접속할 수 있다.

#### Acceptance Criteria

1. THE System SHALL 이름 입력값을 2자 이상 30자 이하로 제한하며, 공백 제거 후 저장한다. ✅
2. THE System SHALL 이메일 입력값을 이메일 형식으로 제한하고 255자 이하로 검증하며, 소문자로 정규화하여 저장한다. ✅
3. IF 이미 가입된 이메일로 가입을 시도하면, THEN THE System SHALL 가입 화면에 "이미 사용 중인 이메일" 오류 메시지를 표시한다. ✅
4. THE System SHALL 휴대폰 번호 입력을 010으로 시작하는 11자리 한국 휴대폰 번호로 제한하며, 하이픈 포함/미포함 모두 허용한다. ✅
5. THE System SHALL 휴대폰 번호를 하이픈 제거한 숫자 11자리 형식(예: `01012345678`)으로만 저장한다. ✅
6. THE System SHALL 비밀번호 입력을 8자 이상 64자 이하, 영문+숫자 조합 필수로 제한한다. ✅
7. THE System SHALL 비밀번호 재입력 값이 비밀번호와 일치하는지 검증한다. ✅
8. THE System SHALL 서비스 이용약관 및 개인정보 처리방침 동의를 필수 체크 항목으로 처리한다. ✅
9. WHEN 가입에 성공하면, THE System SHALL 로그인 화면으로 이동하고 녹색 알림 "회원가입이 완료되었습니다."를 표시한다. ✅
10. THE System SHALL 가입 시각을 한국 표준시(Asia/Seoul) 기준으로 저장한다. ✅
11. THE System SHALL 비밀번호 원문은 저장하지 않고 BCrypt 해시만 저장한다. ✅
12. IF 입력값 유효성 검사에 실패하면, THEN THE System SHALL 동일 화면을 유지하고 오류가 발생한 필드 바로 아래에 빨간 오류 메시지를 표시한다. ✅

### Requirement 2: 로그인

**User Story:** As an 인증된 회원, I want 등록된 계정으로 시스템에 접속할 수 있기를, so that 회원 관리 화면을 이용할 수 있다.

#### Acceptance Criteria

1. THE System SHALL 이메일 입력을 이메일 형식, 255자 이하로 제한한다. ✅
2. THE System SHALL 비밀번호 입력을 64자 이하로 제한한다. ✅
3. WHEN 이메일과 비밀번호가 일치하면, THE System SHALL 회원 관리 화면으로 이동한다. ✅
4. IF 이메일 또는 비밀번호가 일치하지 않으면, THEN THE System SHALL 폼 상단 빨간 알림 박스에 오류 메시지를 표시하며 어느 쪽이 틀렸는지 알 수 없도록 한다. ✅
5. THE System SHALL 입력된 이메일을 소문자로 변환한 후 저장된 값과 비교한다. ✅
6. WHEN 로그인에 성공하면, THE System SHALL 세션을 생성하고 세션 ID를 새로 발급(교체)한다. ✅
7. WHILE 비활동 시간이 30분을 초과하면, THE System SHALL 세션을 자동 만료 처리한다. ✅
8. WHEN 로그인에 성공하면, THE System SHALL 최근 로그인 시각을 한국 표준시 기준으로 업데이트한다. ✅
9. WHEN 이미 로그인된 사용자가 로그인 또는 회원가입 화면에 접근하면, THE System SHALL 회원 관리 화면으로 이동시킨다. ✅
10. THE System SHALL 존재하지 않는 계정에 대해서도 비밀번호 비교 연산을 수행하여 응답 시간으로 계정 존재 여부를 추정할 수 없도록 처리한다. ✅

---

### Requirement 3: 로그아웃

**User Story:** As an 인증된 회원, I want 시스템 이용을 마치고 안전하게 접속을 종료할 수 있기를, so that 다른 사람이 내 계정으로 접근하지 못하도록 할 수 있다.

#### Acceptance Criteria

1. THE System SHALL 로그아웃 요청을 POST 방식으로만 처리하며, 주소창 직접 입력으로는 로그아웃이 불가하다. ✅
2. WHEN 로그아웃 요청이 처리되면, THE System SHALL 서버 세션을 즉시 삭제하여 이후 접근을 차단한다. ✅
3. WHEN 로그아웃이 완료되면, THE System SHALL 로그인 화면으로 이동하고 녹색 알림 "로그아웃되었습니다."를 표시한다. ✅

---

### Requirement 4: 회원 목록 조회 및 검색

**User Story:** As an 인증된 회원, I want 등록된 회원 전체를 조회하거나 특정 회원을 검색할 수 있기를, so that 회원 현황을 파악할 수 있다.

#### Acceptance Criteria

1. WHEN 인증된 회원이 회원 관리 화면에 진입하면, THE System SHALL 전체 회원 목록을 자동으로 표시한다. ✅
2. THE System SHALL 이름, 이메일, 휴대폰 번호 세 항목을 동시에 키워드로 검색할 수 있다. ✅
3. THE System SHALL 검색어 및 대상 필드를 소문자로 변환한 후 비교하여 대소문자를 구분하지 않고 검색한다. ✅
4. THE System SHALL 검색어가 포함된 모든 회원을 부분 일치로 표시한다. ✅
5. THE System SHALL 조회 결과를 회원 등록 순서(ID 오름차순)로 정렬하여 표시한다. ✅
6. THE System SHALL 조회 결과에 번호, 이름, 이메일, 휴대폰 번호(마스킹), 가입일시, 마지막 로그인 일시를 표시한다. ✅
7. THE System SHALL 휴대폰 번호를 조회 시 중간 4자리를 숨김 처리하여 표시하며(예: `010-****-5678`), 미등록 시 "미등록"을 표시한다. ✅
8. THE System SHALL 조회 결과 상단에 총 인원 수(총 N명)를 표시한다. ✅
9. IF 로그인하지 않은 상태에서 API를 호출하면, THEN THE System SHALL HTTP 401 오류 및 한국어 오류 메시지를 반환한다. ✅

---

### Requirement 5: 화면 접근 제어

**User Story:** As a 시스템, I want 로그인하지 않은 사용자가 관리 화면에 접근하지 못하도록 차단할 수 있기를, so that 내부 정보를 보호할 수 있다.

#### Acceptance Criteria

1. WHEN 미인증 사용자가 `/members` 경로에 접근하면, THE System SHALL 로그인 화면으로 이동시킨다. ✅
2. WHEN 미인증 사용자가 `/api/**` 경로에 접근하면, THE System SHALL HTTP 401 JSON 응답을 반환한다. ✅
3. WHEN 사용자가 `/` 경로에 접근하면, THE System SHALL 로그인 여부에 따라 회원 관리 화면 또는 로그인 화면으로 이동시킨다. ✅
4. THE System SHALL 모든 상태 변경 요청(POST)에 대해 CSRF 토큰을 검증한다. ✅
5. IF CSRF 토큰이 일치하지 않으면, THEN THE System SHALL HTTP 403 오류 페이지를 표시한다. ✅

---

### Requirement 6: 오류 처리

**User Story:** As a 사용자, I want 오류 발생 시 적절한 안내를 받을 수 있기를, so that 다음 행동을 결정할 수 있다.

#### Acceptance Criteria

1. IF 입력값 유효성 검사에 실패하면, THEN THE System SHALL 동일 화면에 필드별 오류 메시지를 표시한다. ✅
2. IF 세션이 만료된 상태에서 API를 호출하면, THEN THE System SHALL 브라우저를 로그인 화면으로 자동 이동시킨다. ✅
3. IF HTTP 403 오류가 발생하면, THEN THE System SHALL 오류 화면에 상태 코드, "[접근 거부] 요청이 만료되었습니다. 새로고침 후 다시 시도해 주세요." 안내 및 관리자 연락처(02-6730-3200)를 표시한다. ✅
4. IF 기타 오류가 발생하면, THEN THE System SHALL 오류 화면에 "잠시 후 다시 시도해 주세요." 안내 및 관리자 연락처(02-6730-3200)를 표시한다. ✅

---

### Requirement 7: 초기 데모 데이터

**User Story:** As a 개발자, I want 시스템 시작 시 데모 회원 데이터가 자동으로 생성되기를, so that 개발 및 테스트 환경에서 즉시 기능을 확인할 수 있다.

#### Acceptance Criteria

1. WHEN 애플리케이션이 시작되면, THE System SHALL `member001@bsg-demo.local` ~ `member100@bsg-demo.local` 100명을 자동 생성한다. ✅
2. THE System SHALL 이미 존재하는 데모 회원은 추가 생성하지 않는 멱등성을 보장한다. ✅
3. WHERE 환경변수 `SEED_DEMO_MEMBERS=false`가 설정된 경우, THE System SHALL 초기 데모 데이터 생성을 비활성화한다. ✅
4. THE System SHALL 데모 회원의 비밀번호 원문을 보관하지 않아 데모 회원으로는 로그인이 불가하도록 처리한다. ✅

## 업무 규칙 요약

| 번호 | 규칙 | 확인 상태 |
|------|------|-----------|
| BR-01 | 비밀번호는 BCrypt(강도 기본 12) 해시로만 저장하며 원문은 어디에도 보관하지 않는다 | ✅ |
| BR-02 | 이메일은 소문자로 정규화하여 저장하고 로그인 비교 시에도 소문자 변환 후 비교한다 | ✅ |
| BR-03 | 휴대폰 번호는 010으로 시작하는 11자리 한국 휴대폰만 허용하며 숫자만 저장한다 | ✅ |
| BR-04 | 휴대폰 번호는 조회 시 반드시 중간 4자리를 숨김 처리하여 표시한다 | ✅ |
| BR-05 | 모든 일시는 한국 표준시(Asia/Seoul, UTC+9) 기준으로 저장하고 표시한다 | ✅ |
| BR-06 | 로그인 성공 시 세션 ID를 새로 발급하여 세션 고정(Session Fixation) 공격을 방지한다 | ✅ |
| BR-07 | 세션은 30분 비활동 후 자동 만료되며, 쿠키 방식으로만 관리된다 | ✅ |
| BR-08 | 이메일은 시스템 전체에서 유일해야 하며 동일 이메일로 중복 가입 불가 | ✅ |
| BR-09 | 이름은 공백 제거 후 저장하고 2자 이상 30자 이하여야 한다 | ✅ |
| BR-10 | 비밀번호는 영문과 숫자를 반드시 포함하고 8자 이상 64자 이하여야 한다 | ✅ |

## 현재 구현되지 않은 기능 (개선 검토 후보)

아래 기능들은 일반적으로 필요할 것으로 예상되나 현재 시스템에 구현되어 있지 않다.

- 회원 정보 수정(이름, 휴대폰 번호, 비밀번호 변경)
- 회원 삭제 또는 비활성화
- 비밀번호 찾기 / 재설정
- 권한 등급 구분 (일반 회원 vs 관리자)
- 페이지네이션 — 현재는 전체 목록을 한 번에 표시
- 엑셀 내보내기
- 로그인 실패 횟수 제한 (잠금 정책)
- 회원 상세 정보 화면

## 확인이 필요한 사항

| 번호 | 확인 항목 | 이유 |
|------|-----------|------|
| Q1 | 회원 관리 화면(목록 조회)은 누가 사용하는 화면인가? 내부 운영 담당자 전용인가, 아니면 일반 회원도 가입하여 사용하는 서비스인가? | 권한 구분 없이 로그인 시 전체 회원 목록이 노출되는 구조이므로 접근 정책 확인 필요 |
| Q2 | 오류 화면의 관리자 연락처(`02-6730-3200`)는 현재 유효한 연락처인가? | 코드에 하드코딩되어 있어 변경 시 개발 수정이 필요 |
| Q3 | HTTPS 환경(운영 서버)에서는 `SESSION_COOKIE_SECURE=true` 설정이 적용되어 있는가? | 미설정 시 세션 쿠키가 HTTP 연결에서도 전송되어 보안 위험 |
| Q4 | 데모 회원 100명(`member001~100@bsg-demo.local`)이 운영 환경에서도 생성되지 않도록 `SEED_DEMO_MEMBERS=false`가 설정되어 있는가? | 운영 환경에서 테스트 데이터가 노출될 위험 |
